# Session Wrap-up

After completing significant work on a repository, always:

1. **Review the interaction** for key learnings, decisions, and context
2. **Suggest running `/lessons-learned`** to capture findings in the repo's `CLAUDE.md`
3. Focus on:
   - Design invariants and *why* they exist, not just API behavior (the *what*)
   - Architectural decisions and rationale
   - Non-obvious behaviors, gotchas, and dead ends
   - Key insights discovered during debugging/optimization

The `/lessons-learned` skill handles the full workflow: rubric, FAQ formatting, source verification, and categorization. See the skill for details.
